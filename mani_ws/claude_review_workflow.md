# Claude 工作审查框架

## 使用流程

```
工作对话（生成 → 保存文件）→ 审查对话（读文件 → 输出审查结果）
```

> 两个对话都必须使用 Claude Code（有文件读写权限）

---

## 第一步：工作对话收尾模板

> 任务完成后，发送以下内容，让Claude将结果保存到文件

```
请将本次输出整理并保存到 /home/jasper/claude_work_output.md，格式如下：
【任务目标】：
【完成内容】：
【关键假设】：（你做了哪些假设）
【未确认的地方】：（你不确定的部分）
【完整输出】：
（把本次完整的代码/文档/内容放在这里）
```

---

## 第二步：审查对话模板（通用版）

> 新开一个空白 Claude Code 对话，直接粘贴以下内容发送

```
请读取 /home/jasper/claude_work_output.md，作为严格的技术审查员对其进行审查。

审查标准如下，请逐条检查：
1. 【逻辑一致性】内容内部是否有矛盾？
2. 【需求覆盖】是否遗漏了任务目标中的要求？
3. 【关键假设风险】列出的假设是否合理？有无明显错误？
4. 【不确定项处理】标注的不确定部分，是否给出了可接受的处理方式？
5. 【可执行性】输出是否足够具体可以直接使用？

请给出：
- 发现的问题列表（有则列出，无则说"无"）
- 修改建议
- 综合评分：可直接使用 / 需小改 / 需重做
```

---

## 第二步：审查对话模板（代码任务专用）

> 适用于：写代码、调试、算法实现等任务

```
请读取 /home/jasper/claude_work_output.md，作为严格的技术审查员对其进行审查。

审查标准如下，请逐条检查：
1. 【逻辑一致性】代码逻辑内部是否有矛盾或冗余？
2. 【ROS接口】话题名、消息类型是否与项目实际一致？
3. 【QMIX算法】多智能体协作逻辑是否符合QMIX基本假设？
4. 【运行风险】是否有明显的运行时错误风险（类型错误、边界问题等）？
5. 【接口兼容性】与A*路径规划或其他模块的接口是否兼容？

请给出：
- 发现的问题列表（有则列出，无则说"无"）
- 修改建议
- 综合评分：可直接使用 / 需小改 / 需重做
```

## 第二步：审查对话模板（文档/规划任务专用）

> 适用于：写报告、制定计划、整理文档等任务

```
请读取 /home/jasper/claude_work_output.md，作为严格的技术审查员对其进行审查。

审查标准如下，请逐条检查：
1. 【逻辑一致性】内容结构是否清晰，前后是否矛盾？
2. 【需求对齐】是否与比赛要求或评分标准匹配？
3. 【时间可行性】规划节点是否现实（当前距比赛约4周）？
4. 【完整性】是否遗漏关键模块、依赖或风险点？
5. 【可读性】表述是否清晰，目标读者能否理解？

请给出：
- 发现的问题列表（有则列出，无则说"无"）
- 修改建议
- 综合评分：可直接使用 / 需小改 / 需重做
```

---

## 任务是否需要走审查流程

| 任务类型 | 建议 |
|---|---|
| 核心算法 / 架构决策 | 必须走审查 |
| 普通功能代码 | 建议走审查 |
| 项目文档 / 规划 | 建议走审查 |
| 简单解释 / 问答 | 可跳过 |
